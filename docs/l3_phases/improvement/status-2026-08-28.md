## 4. 新規発見

### N1. works.json の 52% がフロントから読まれていない ★最優先

`data/works.json` は 18.4MB（gzip 6.06MB）。フィールド別の実測内訳:

| フィールド         | サイズ  | 比率  | フロントでの用途                                        |
| ------------------ | ------- | ----- | ------------------------------------------------------- |
| `descriptionFirst` | 8.87 MB | 50.0% | **なし**（詳細は `series/<id>.json` から読む）          |
| `credits`          | 2.56 MB | 14.4% | あり — 一覧の人物フィルタ（`filter.ts:127`）            |
| `tags`             | 2.01 MB | 11.3% | あり — タグ AND フィルタ                                |
| `relatedSeries`    | 0.84 MB |  4.7% | **なし**（詳細は `series/<id>.json` から読む）          |
| その他 18 項目     | 4.1 MB  | 19.6% | あり                                                    |

**根拠**: 詳細画面は `loader.ts:77` の `series/<seriesId>.json` を読み、`detail.ts:211 renderDetail` は
`SeriesDetail` 型を受け取る（`types.ts:173-191`）。`Work.descriptionFirst` / `Work.relatedSeries` を参照する
本番描画経路は存在しない（`web/src` 全体の grep で一致するのは `types.ts` の宣言のみ。他の一致は
`tests/web/*` の fixture）。`scripts/` 側も `project.mjs:112,412` が書き出しているだけで、
ops-health を含め読む側はない。

**対処**: `project.mjs:112`（日次）と `:412`（毎時）から 2 フィールドを落とし、`types.ts` の `Work` からも削除する。
`Work` から消せば typecheck が参照漏れを検出するため、安全に外せる。

**実測効果**: 18.4MB → 8.34MB（-55%）、gzip 6.06MB → **2.41MB（-60%）**。初回表示の転送量がそのまま減る。

**受け入れ条件**:

- [ ] `pnpm typecheck` が緑（`Work` からフィールドを消しても参照エラーが出ない＝未使用の証明）
- [ ] `data/works.json` を再生成し、gzip サイズが 3MB 未満
- [ ] 詳細画面のあらすじ・関連シリーズが従来どおり表示される（`series/<id>.json` 由来）
- [ ] 一覧の人物フィルタ（`?credit=`）が従来どおり動作する
- [ ] `pnpm ops:health` が PASS（works.json のスキーマ検査に引っかからないこと）

**次の一手（別 PR）**: `credits`（2.56MB）は `?credit=` が有効なときだけ読む別 JSON へ分離する。
これで一覧の初期ロードはさらに約 1/3 減る。

増分の中身はシリーズ所属の是正ロジック（A2 / B7 / B7b / D3b）で、**最も複雑な差分が最も検査の薄い層に入り続けている**
（scripts/ は typecheck 圏外＝C20）。C8（分割）と C20（型検査）は「中長期」枠から前倒しすべき。

### N3. `phase2.md` に生の NUL バイトが混入している

byte offset 8536（81 行目）に実バイトの `\0` がある（`title + '\0' + n` というソルト例を、
エスケープ表記ではなく実バイトで書いてしまったもの）。結果として git・grep が binary 扱いし、
prettier の対象外・差分レビュー不能になっている。**本 PR で修正済み**（`\\0` 表記へ）。

### N4. 作品別のハードコード hint がコードに侵入している

`scripts/series-hints.mjs` の `SERIES_TITLE_HINTS`（現在 2 件）は、GitHub runner から取得できない作品を
手で補う例外表。衝突検知（`mergeSeriesTitleHints` の throw）があるのは良いが、**件数が増えるほど
「データの例外」がコードとして固定化**し、`list.json` 掲載後も残り続ける。
→ JSON へ外出しし、`{ seriesId, title, 確認日, 由来 }` を持たせて、日次で「list.json に載ったら hint を外す」棚卸しを提案。

### N5. ワンオフ/診断スクリプトが `scripts/` 直下に混在している

`screenshot.mjs`（135 行）/ `screenshot-top.mjs`（118 行）/ `shoot-top.mjs`（106 行）は**役割が重複した 3 本**。
`analyze-ep-patterns.mjs`・`diagnose-series.mjs`・`reproject.mjs` を含め `package.json` の `scripts` に未登録で、
本番の取得パイプライン（`fetch.mjs` 系）と同じ階層に置かれている。
→ `tools/` へ隔離し、スクショ 3 本は引数（screen × theme × viewport）を取る 1 本へ統合する。
