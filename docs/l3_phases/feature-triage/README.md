4. **並び替え 8 種のうち「累計コメント数」「平均コメント数」**を使っているか。使っていなければ外したい（B4・優先度は低い）。
5. **投稿年スライダー**を「放送年」に置き換えてよいか（削除でもよいか）（A5）。
6. **トップのタグ**: クイックアクセス下のランダムタグのマーキーと、「タグから探す」のランダム行のどちらを残すか（B3）。
7. **設定の「取得できていないシリーズも表示」「取得不可の作品を表示」**を使っているか。1 つにまとめるか、削除するか（B2）。

## 付録: 本番データの取り出し方（再現手順）

```sh
git fetch --deepen=60 origin state:refs/remotes/origin/state
# 最新の公開 JSON
git show origin/state:works.json > /tmp/works.json
# 日次コミット（[daily]）ごとの ranking.json / works.json
for c in $(git log --format=%h --grep=daily origin/state); do
  d=$(git log -1 --format=%cs "$c"); git show "$c:ranking.json" > "/tmp/ranking-$d.json"
done
```

- Hot の安定性: 隣り合う日の `ranking.hot` の TOP10/TOP20 で `seriesId` の重なりを数える。
- 別の式での試算: 隣り合う日の `works[].totalViews` の差を、そのシリーズの前日比の再生増とみなして並べ直す。現行式をこの方法で再現すると TOP10 の重なりは 3.1（実際の hotScore では 2.7）で、実際の値とほぼ一致する。
- 関連シリーズの試算: `scripts/etl/series.mjs` の `computeFranchiseKeys` を本番の `works.json` に直接かけ、タグ側だけ条件を変えて比べる。
